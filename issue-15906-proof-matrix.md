## Data flow and render-path inventory

### Changed producers and selectors

- `CursorDriver.usage.scan` now passes every Cursor usage instance's ID, display name (configured `displayName`, default `Cursor`, or instance ID fallback), and merged environment to `CursorUsageAccounts.scan`. Usage scanning enumerates configured instances, including disabled ones, and synthesizes the default instance when absent; a provider being disabled is not an instruction to omit its history.
- A configured, trimmed `CURSOR_API_KEY` wins over a stored T3 sign-in. A valid stored sign-in supplies its own `backendUrl`; configured keys use the **host process** `CURSOR_BACKEND_URL`, not an instance-specific backend override. No own key/sign-in falls back to the host's login path. Expired sign-in, credential-store failure, rejected key, exchange/history HTTP failure, malformed response and timeout yield named failures; missing host auth can yield no source. These are different seed causes, but identical layouts collapse into N01/N02 rather than duplicate screenshots.
- Host login source: file on Linux/Windows; Keychain on macOS unless credential-store mode is `file`. macOS, no incompatible token/key/memory mode, and Keychain disabled yields `action: enableCursorKeychain`. Host API key matching an instance key suppresses the generic CLI-login notice, except when host `CURSOR_AUTH_TOKEN` or memory credential-store mode also applies. Token/memory/unbilled-host-key branches retain that notice.
- Cold account read: no cached data, `refreshing: true`, empty records and no error notice until completion. Cached read: records remain during refresh; a subsequent failure returns `partial` plus the instance-prefixed notice. Success has no notice. Successful accounts carry `hostId: cursor.com`, account-hash `volumeId`, and `cursor-account:<hash>` resolved path. Different credentials on one account choose the readable/freshest source; different accounts add. Removed/rotated instance-key caches are pruned.
- `needsCursorKeychainAccess(summary, providers)` requires an action source **and** a ready Cursor provider. `cursorKeychainAccessEnvironments(selected)` returns no prompts if **any selected environment with needs=false** has a Cursor account source (`provider=cursor`, `hostId=cursor.com`); otherwise it returns all selected environments with needs=true. Account source presence, not positive buckets/status/tokens, controls suppression. The changed case is an environment with both its own instance account source and needs=true: it no longer suppresses its own or other waiting environments' prompt. Null summaries and empty sources do not suppress. A non-ready provider makes needs=false even if an action source exists.
- The shared selector has exactly two production callers: web `UsagePage` and mobile `UsageScreen`. `needsCursorKeychainAccess` is called by each client's `state/usage.ts`; there are no other production prompt render consumers. Shared `refreshUsageLimits` in the same file is unchanged.

### Web and desktop callers, layout and branches

- Sole component caller: route `/_chat/usage`, public path `/usage`, renders `UsagePage()` with no props. Sidebar Usage, command palette “Open usage,” `usage.open` keybinding, and direct navigation converge here. Desktop wraps this renderer. Provider settings configure instances/Keychain permission; they are not alternate usage-total renderers.
- `UsagePage` derives selected environments, hidden providers, merged/shown usage, time window, metric, pending/kept data, permission availability, Cursor prompt candidates, and ChatGPT-sharing visibility. Default stored metric is Limits; explicitly select Cost/Tokens for history evidence. Preferences persist metric/window/hidden providers. Environment selection is local page state.
- Main branch order: zero selected environments → connect/select copy; Limits → `UsageLimitsSection`; no shown answer → skeleton; no selected environment with diagnostics access → per-environment error copy; otherwise → `UsageOverview`. No Cursor history failure notice is rendered inside the Limits branch; its changed content is the Cursor enable prompt only.
- `UsageOverview` notices: unique message strings, visible provider, no `action`, and (`partial` or `failed` or Cursor). Thus Cursor `missing` also displays, while the Keychain action's message is replaced by the enable UI. Zero/one/many notices and long instance names change height/wrapping. Identical full message strings across sources collapse; different instance prefixes remain distinct.
- Summary rows contain active providers with data **or loading providers**, and zero/one/many Cursor enable rows inserted after Codex/Claude. Multiple accounts still give one Cursor usage row. Each enable row gets `environmentId`, label, `showEnvironment = selectedEnvironmentCount > 1`, and callback. Single selected environment: `Cursor`; multiple selected: `Cursor · <environment>`, truncated. One pending target disables/busies its own Enable button. Hover/focus tooltip explains Keychain. Limits uses a separate bordered section, wrapping buttons: one prompt candidate → `Enable`; multiple candidates → `Enable on <environment>` (candidate count, not selected count).
- Figures: Cost/Tokens change headline, provider value/share, chart units and model ordering; one session uses singular. Loading without data uses `-` and invisible session/share text; loading cached data dims the existing numbers. Kept previous-window data dims all providers until replacement. Chart uses day/hour arrays, active provider count and loading set; zero series/zero scale versus positive paths, one/many periods, hover/focus tooltip. Timezone and 12/24-hour setting alter hourly labels.
- Totals always render in overview; token type/cost breakdown appears only when `totalTokens > 0`. Cost shows the unpriced-details popover when `unpricedShare > 0`; known/unknown model price changes numeric cost to `Unpriced`, share can be blank, positive/zero values change model bars. Cost-by-speed appears only for fast/ultrafast cost (Cursor account records are standard; this is unchanged and not newly reachable from this diff). Model breakdown empty/nonempty; time breakdown empty/nonempty with active-provider columns; selected model opens existing detail/price flow. Mobile has different cost/empty branches below.
- Environment filter labels: All / one label / count; menu includes environment count, connection/loading/stale/partway/ready/error/contract mismatch states, partial warning, duplicate-source coverage notice, and Model prices action. `hasIssue` uses environment errors or contract mismatches, not a source-level Cursor failure. Provider filter labels: All / none / one provider / count. Hiding Cursor removes Cursor totals, notices, charts and enable prompt; it does not stop the server from scanning.
- Responsive branches: modal is full screen below `sm`, inset/capped above it; overview becomes two columns at `lg`; totals 2→5 columns at `md`; model Share column hidden below `sm`; header segmented controls above `@4xl/usage-header`, compact selects below. Header date label has an `@7xl` branch; the normal modal is capped at `80rem` and its inner header is smaller, so that branch is not a reachable default-layout requirement. Light/dark use existing theme tokens, no new JSX theme branch. `redesignEnabled` changes chevron visibility and hides the period control on Limits; legacy design disables it instead. One representative legacy Limits transition suffices; no full theme/design Cartesian product.
- Interactions: open/close route (Esc/close/backdrop), environment/provider selection, metric/window controls and usage keybindings (guarded for inputs/open dialogs/palette), refresh with duplicate-click prevention, chart pointer/focus tooltip, model/time breakdown, model dialog open/close and Set price/Model prices flow, unpriced popover, Keychain tooltip/Enable, Settings disable. Newly affected ones are covered by recordings V01/E01/F01/K07/T01–T03; ordinary modal dismissal and price saving are unchanged controls, not separate required fixtures.

### Mobile callers, layout and branches

- `UsageRouteScreen({ workspace? })` is called by the `SettingsUsage` stack screen (`settings/usage` deep link) and by `WorkspaceExtraTab` with `workspace=true`. It passes `workspace` and route `tab` to `UsageScreen`; explicit `tab=usage` selects history, anything else/default selects Limits. Workspace changes screen shell/navigation; it does not select another data pipeline.
- No provider filter. Shared selector receives selected environments directly. Tabs Usage/Limits, window 24h/7d/30d/90d, and metric Cost/Tokens are separate controls. Android stacks window and metric controls; iOS uses a horizontal arrangement and a native header menu. Environment-filter menu visibility depends on available environments or explicit selection; default/all versus explicit selection changes its icon. Android is the allowed native capture surface here.
- Usage branch order: duplicate-source text (if any), pending scan text, zero selected connect/select copy, diagnostics-denied errors, then unique source notices plus updating/chart/providers/totals/cost/models. Unlike web, duplicate-source notice is inline and no provider filtering occurs. A source failure remains visible independently of the updating opacity wrapper.
- Updating state dims content (normal/reduced-motion timing) and can show a capped/truncated progress label/spinner. Tabs fade in with system reduced-motion handling. Pull-to-refresh is available for Limits or readable diagnostics; refreshing is guarded against duplicate requests. These are recording states.
- `ChartCard`: Cost headline with API-rate footnote versus Tokens with sessions; activity requires a period with positive tokens, otherwise explicit empty-chart copy. Provider legend zero/one/many wraps. Provider section absent when no providers and no prompts; otherwise cost/token ordering, share bars, first/subsequent border, plus prompt rows inserted after Codex/Claude. Prompt label shows environment when selected count >1; it shrinks rather than web truncation. Enable button uses loading spinner and disabled state.
- Totals use six half-width cells; active-hour/day average, observed input zero/nonzero, cached share, and cost zero/nonzero alter details. Cost section absent if cost <=0; visible category segments filter positive values, `Other` appears at >=$0.005, speed bar only for premium speeds (unchanged standard-only Cursor data cannot add it). Models absent when none; otherwise cost/token sorting, unknown-cost descriptions and value, one-line model-name truncation, first/subsequent borders. No mobile model-click detail interaction exists in this component.
- Limits has the same candidate-dependent single/multiple Enable copy and insertion position as web, wrapped native buttons, and empty-subscription copy only when no pools/notices/failures/prompt/external links. Cursor account usage totals do not create subscription pool cards. Other pools' number of accounts/exhaustion/refill interactions are unchanged and outside this matrix.

**H — labelled harness:** Use unchanged production Usage components, state selectors and RPC contracts with synthetic summaries/provider presentations and controlled command results. **Refresh timing:** Cursor success and failure caches use a 60-second TTL. `awaitRefresh:true` waits for an eligible refresh; it does not bypass a fresh cache or failure cooldown. Prepare stale cache / age the fixture before recording, or use a labelled server-clock harness. Gate stub completion to capture real in-flight states, release well before the per-page 10-second timeout, then await response/summary milestones. Do not infer completion from arbitrary sleeps. For settings/sign-in removal, record the actual refetch/settings milestone and source set.
